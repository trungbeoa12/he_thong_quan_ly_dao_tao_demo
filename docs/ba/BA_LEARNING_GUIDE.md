# BA Learning Guide

This guide explains how BA learners should use the TMS project during the full training lifecycle.

## Phase 1 - Business Understanding

Read:

- `01_business_request/business_request.md`
- `02_stakeholder_analysis/stakeholder_analysis.md`
- `03_as_is/as_is_process.md`

Questions:

- What business problem does TMS solve?
- Which departments are affected?
- Which reports are currently hard to produce?
- What risks exist when training data is managed by Excel?

## Phase 2 - Requirement Gathering

Ask stakeholders:

- How is Course different from Training Class?
- Who can create a class?
- Who can register employees?
- When is manager approval required?
- What conditions define course completion?
- Which costs are included in training cost?

## Phase 3 - URD

Learners draft the URD from business language before comparing with the project reference URD.

## Phase 4 - SRS

Learners break requirements into functional specifications for Course, Class, Registration, Attendance, Result, Cost, and Report.

## Phase 5 - Data Analysis

Learners identify entities, fields, relationships, primary keys, foreign keys, sources, and transformations.

## Phase 6 - API

Learners map:

`UI -> API -> Service -> Database`

## Phase 7 - Development Understanding

Learners trace Controller, Service, Repository, Entity, DTO, Mapper, Database, and Test Case.

## Phase 8 - SIT

Learners write and execute test cases based on SRS.

## Phase 9 - UAT

Learners perform business scenario testing with stakeholders.

## Phase 10 - Change Request

Learners analyze the impact of new requirements after go-live.
